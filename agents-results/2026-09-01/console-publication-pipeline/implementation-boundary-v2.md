# Console Blueprint Local-Completion Boundary

- Request authority: repository owner requested implementation of the current `docs/prototypes/console-dev-blueprint.html` on `main`.
- Source contract: the design states in sections 5--9, including its capability-state labels. This revision completes every capability that can be implemented and verified wholly inside this repository.
- Out of process: real literature-provider retrieval, production identity/OAuth, payment collection, and paid-upstream account routing require a selected provider, credentials, consent/data-retention policy, and commercial authorization. The implementation must expose only fail-closed `not_configured` boundaries for these dependencies.
- Research boundary: no new HTTP mutation path may alter research workspaces, traces, source registry, mathematical status, novelty status, or promotion. Existing review submission remains the only research write endpoint.
- Operations boundary: accounts, credits, seats, and configured upstream metadata live outside research workspaces and must not affect replay bytes or research conclusions.
- Completion criterion: each local record is durable, canonical, deterministic, validates strictly on reload, has negative tests, and only appears as live UI data when an explicit verified projection exists.
