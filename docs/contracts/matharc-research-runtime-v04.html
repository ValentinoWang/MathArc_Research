MathArc 原生研究运行时 v0.4 产品合同

权威边界

  • MathArc 原生运行时拥有研究运行的执行状态、任务调度、代际提交、恢复计划、候选导入和运行控制权威。
  • 数学结论仍只由 ResearchTrace 的验证门和晋升方法改变；RuntimeStore 不得把运行成功直接写成 PROVED。
  • 模型 API、Codex、Claude Code 和本地进程都是可替换后端；后端只返回不可变的 WorkerExecutionResult。

运行身份层级

运行身份必须按以下层级区分：workspace_id → trace_id → runtime_run_id → generation_id → worker_id → execution_id → candidate_id → evidence_id。

runtime_run_id 是运行时实例身份，不复用既有 ResearchTrace.run_id 的语义。身份缺失、跨工作区引用或来源摘要不匹配时，导入和恢复均失败关闭。

单任务与候选合同

  • RUN1 定义 ResearchRunSpec、ResearchWorkerSpec、WorkerExecutionResult、CandidateEnvelope 和 RuntimeActionReceipt。
  • 协调器结合评价器摘要、运行身份、源码身份、工具注册表摘要、预算和产物摘要组装 CandidateEnvelope。
  • 验证阶段只校验 CandidateEnvelope 的身份约束，不负责第一次定义候选包。

冻结输入、并行与归并

  • 每一代开始时生成不可变 GenerationInputSnapshot，包含 trace_digest、contract_digest、agenda_digest、worker_spec_digest 和 tool_registry_digest。
  • 成员只能读取冻结快照和隔离工作区，不能直接修改共享 ResearchTrace。
  • 唯一的 GenerationReducer 负责稳定排序、冲突检查、重复去重、部分失败、最低完成成员数、超时和迟到结果归属，并生成 GenerationCommit。
  • GenerationClosePolicy 决定代际关闭；关闭后迟到结果不得改写已关闭代际。

持久化、恢复与数学验证

运行事件采用哈希链和原子快照，候选、费用和执行回执使用带来源身份的幂等账本。恢复只能从最后一个完整 GenerationCommit 边界生成。验证器产生 VerifierReceipt，只有独立重放和范围检查通过的候选才可转换为 EvidenceRecord。

邀请制控制台与试点运行环境

  • 邀请制控制台只投影 RuntimeStore，通过 Cookie 会话和权限边界提供登记动作。
  • 服务端不得接受任意命令、工作目录、环境变量、可执行文件或参数；敏感字段和主机路径必须递归脱敏。
  • OPS1、OPS2、OPS3 必须先完成部署守护、健康日志、配额、备份恢复、回滚和数据清理，DOG2 才能进入真实研究。
  • VER6 只能在独立验证、范围检查和来源身份均通过后开放数学证据晋升。
  • UX2 只允许已邀请主体读取受控运行投影，并拒绝未授权的运行操作。
  • UX3 只接受登记过的运行动作和目标身份，不接受任意命令或参数。
  • UX4 必须在投影层递归脱敏敏感字段、主机路径、命令和异常堆栈。
  • UX5 必须从 RuntimeStore 读取运行状态，并展示停止、暂停、继续和重新验证的可审计回执。
  • UX6 的人类验收必须同时记录邀请权限、动作边界和用户对运行状态的理解。
  • DOG2 必须使用两代真实研究和持久运行时证据，且不得绕过验证晋升。
  • DOG3 必须通过越权命令、跨工作区写入、重复费用和迟到结果攻击演练。
  • DOG4 必须绑定发布决策、验证报告、部署身份和远端回读证据。
  • OPS1 必须固定部署配置、持久目录、密钥来源和进程守护，并保留可重放日志。
  • OPS2 必须提供健康检查、日志、并发与费用配额以及备份恢复的机器证据。
  • OPS3 必须提供部署、重启、回滚和用户数据清理的可验证收尾证据。

零容忍不变量

  • 错误数学晋升、重复执行、重复费用、重复候选导入、跨工作区写入、关闭代际被迟到结果改写、公共接口敏感信息泄露、无权限运行动作均必须为 0。
  • 建立 MathArc 原生运行时所有权与依赖允许清单，阻断治理工具链进入产品运行路径。
  • 保留 ResearchTrace 的数学结论晋升权威，并证明运行状态不能直接变成正式证明。
  • 定义可版本化的研究运行合同、身份层级、候选包和运行动作回执。
  • 建立可重放的运行存储，使事件、快照和候选导入在进程重启后保持一致。
  • 建立有预算、种子和最小试跑门槛的评价器合同，失败时不启动完整研究。
  • 将各类执行后端统一为 MathArc 请求，只返回不可变 WorkerExecutionResult 并由协调器组装候选包。
  • 独立验证单任务从试跑、执行到候选回传的闭环，并阻断候选越级晋升。
  • 把研究路线和角色编译为带机制、预算、目标和隔离写入区的运行拓扑。
  • 接入已批准的动态任务并执行一次性、可审计的任务启动。
  • 在持久化和恢复能力之后实现有界并行、冻结输入和隔离工作区调度。
  • 按执行回执记录实际资源消耗，并对语义重复实验做确定性去重。
  • 独立验收多成员一代归并、冲突、部分失败和迟到结果规则。
  • 定义冻结输入、代际提交、GenerationReducer 和 GenerationClosePolicy 的持久边界。
  • 以带来源身份的幂等账本保存候选、费用和执行回执，拒绝来源漂移。
  • 实现停止、排空、暂停、继续和取消的显式运行状态协议。
  • 从最后一个完整 GenerationCommit 生成可重放的崩溃恢复计划。
  • 独立验收冷启动恢复、幂等恢复和不跳代不重复规则。
  • 把普通执行输出标准化为带完整出处的探索候选，隔离于正式证据。
  • 将疑似反例送入独立复核队列，未复核前不改变研究路线或结论。
  • 从真实运行蒸馏带身份和候选出处的研究记忆。
  • 把失败、经历和评审缺口编译为明确消费上一代事实的下一代议程。
  • 独立验收连续两代提交、路线变化和上一代事实消费。
  • 定义候选进入验证阶段所需的身份约束和 VerifierReceipt，而非重新定义候选包。
  • 把候选绑定到具体命题、量词、对象和范围，拒绝范围扩大与对象错配。
  • 为候选生成干净环境的独立重放计划，排除同实现自证。
  • 仅将通过 VerifierReceipt 的候选转换为带出处的 EvidenceRecord。
  • 记录命题、源码、评价器或候选身份变化导致的证据失效。
  • 独立验收验证汇合、篡改检测、越界阻断和非独立结果拒绝。
  • 把 RuntimeStore 状态投影到现有控制台数据合同，保持单一真相源。
  • 复用邀请制 Cookie 会话和权限边界，阻断无权用户的运行动作。
  • 提供登记动作的幂等运行控制服务，拒绝任意命令、目录、环境和参数。
  • 建立统一中文运行视图并递归脱敏密钥、路径、命令、环境变量和堆栈。
  • 实现断线重连后从服务端快照恢复的实时研究控制台。
  • 独立完成人类浏览器验收，覆盖桌面、移动端、权限负路径和完整操作流。
  • 固定首个真实任务、评价器、范围、预算和可重放的单成员基线。
  • 在运维闭环完成后执行两代真实并行研究并证明第二代消费第一代事实。
  • 执行崩溃、篡改、虚假反例、重复导入和权限攻击演练并验证安全恢复。
  • 汇编邀请试点的人类验收与发布证据，作出独立发布决策。
  • 固定试点部署配置、持久目录、密钥来源和进程守护方式。
  • 建立健康检查、日志、配额、备份和恢复观测闭环。
  • 独立验收部署、重启、回滚和试点用户数据清理。
