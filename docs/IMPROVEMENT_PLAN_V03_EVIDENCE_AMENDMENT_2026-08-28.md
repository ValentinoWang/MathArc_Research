# IMPROVEMENT_PLAN_V03 evidence amendment — 2026-08-28

This amendment narrows historical implementation-status prose in `IMPROVEMENT_PLAN_V03.md`. It does not change the research roadmap. Where the older “落地状态” wording conflicts with this file on validation evidence, this file is authoritative.

## Claude Code end-to-end wording correction

The older plan says the W1-2 bridge “已用真实 `claude` CLI 端到端验证” and then narrates a successful falsifier turn. That historical manual run may have happened, but its trace/ModelUsage was not versioned in the repository. Under the repository’s own evidence-gating rule, the sentence must therefore be read as:

> **Historical manual smoke observation; not current authoritative evidence.**

It must not be used by itself to claim that the current branch or release has a verified real-Claude end-to-end path.

The current evidence-producing contract is:

```bash
make smoke-claude
```

The target uses synthetic mathematical input, invokes the authenticated Claude Code CLI through the same proposal-only worker bridge, and writes a sanitized artifact under `artifacts/smoke/claude-code.json` containing structured proposal output, public trace, ToolCallRecord and ModelUsage. Raw prompt/stdout are intentionally not persisted.

A milestone may state “real Claude Code end-to-end smoke verified” only when either:

1. that milestone commits an approved sanitized smoke artifact; or
2. its committed G0-c baseline records the content hash of the approved smoke artifact.

Absent one of those records, the correct wording is “real-model smoke entrypoint implemented; current smoke evidence pending.”

## Validation-count wording correction

Older status prose hand-maintains numbers such as 135 tests and 39 mypy source files. A later audit observed 155 tests / 40 files, and subsequent v0.3 work added further modules and regressions. Therefore no fixed number in the planning prose is current SSOT.

Current counts are generated by the Gate 0 tools:

- `scripts/run_unittest_suite.py` → tests discovered/run, failures/errors, total skips, SMT discovered/executed/skipped;
- `scripts/ci_preflight.py` → Python/formal capability versions;
- `scripts/write_g0c_baseline.py` → dynamic `matharc/v02/**/*.py` count plus artifact SHA-256 digests.

The dated G0-c baseline generated by `make baseline` is authoritative for the corresponding commit. Historical numbers remain historical observations only.

## Gate wording correction

Any older sentence equating bare `make ci` exit 0 with the unique authoritative Gate 0 is superseded by the 2026-08-28 Gate amendment:

- `make ci` = developer/degraded-capable loop;
- `make ci-full` = authoritative local gate, formal/z3 required and SMT must execute;
- `make clean-ci` = clean committed-checkout reproduction;
- `make baseline` = versioned G0-c evidence producer.
