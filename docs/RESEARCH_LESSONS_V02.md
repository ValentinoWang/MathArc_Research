# MathArc Research v0.2：从长期数学证明对话抽取的研究协议

## 0. 文档边界

本文总结可公开、可审计的研究动作：问题如何拆解、候选命题为何失败、证据如何改变研究方向，以及何时允许提升结论。它不保存逐 token 的私有思维链。系统展示的是下列六元记录：

1. 当前目标；
2. 已声明前提；
3. 本轮动作；
4. 可观察结果；
5. 证伪测试；
6. 接受、修正、阻塞或拒绝的决策。

这比展示未经整理的内部草稿更适合研究协作：每一项都能连接到命题节点、工具调用、证据和失败记录。

---

## 1. 从对话中反复出现的有效研究循环

MathArc v0.2 使用的最小循环不是“让模型继续想”，而是

```text
定理合同
  → 命题 DAG
  → 承重义务选择
  → 机制不同的路线
  → 最便宜的 kill test
  → 原子推导或证书
  → 独立重构
  → 命题晋升或失败传播
  → 失败记忆
```

其中任何一步都不能由语言流畅度代替。

### 1.1 定理合同先于证明

合同必须暴露：

- 精确量词；
- 对象的域、陪域和正则性；
- 外部定理及其版本；
- 成功标准；
- 明确不声称的内容。

这一步解决了多个项目中的同类问题：局部构造被误称为全局结论、有限体积结果被误称为无限体积理论、一个商映射的满射性被误称为原猜想已经解决。

### 1.2 选择承重节点，而不是选择最容易写的节点

命题节点的优先级由以下因素决定：

- 是否位于目标的祖先闭包中；
- 失效后会阻塞多少后继节点；
- 是否承担全称量词、极限交换、完备化或独立性；
- 其依赖是否已经闭合；
- 是否存在便宜而有区分力的反例测试。

因此“又证明了一个漂亮引理”不一定产生研究进度。只有关闭目标依赖图中的承重节点，才增加逻辑闭合度。

### 1.3 路线按机制区分，不按措辞区分

两条路线只有在核心机制不同的时候才算并行路线。例如：

- 不变量障碍与显式构造；
- 紧性归约与组合证书；
- 形式化证明搜索与反例枚举；
- 谱估计与算子代数重构。

把同一个 induction argument 改写成“递推路线”和“层级路线”不增加路线多样性。v0.2 为每条路线保存 `mechanism_signature`，完全相同的签名会被拒绝。

### 1.4 先运行 kill test，再扩大证明

最便宜的证伪测试通常比继续展开十页推导更有价值。典型 kill test 包括：

- 最小维数、最小阶数和边界参数；
- 交换量词后构造反例；
- 检查完成化、闭包或极限是否保持所需性质；
- 对生成器和检查器做篡改测试；
- 用第二实现重建证书；
- 在定义的弱版与强版之间测试结论实际使用了哪一个。

失败不是一次无效调用。它应生成一个结构化记录：触发条件、失败类型、最小见证、失效节点、可行修复和可复用教训。

## 2. 主要失败类型及其来源

### 2.1 `SCOPE_OVERREACH`：结论范围超过证据范围

反复出现的模式：

- 在有界 Wilson 网上完成代数重构，却把它称为四维 Yang–Mills 存在性与质量间隙的最终证明；
- 得到某个无限族的优美标号拼接，却把它等同于优美树猜想的全称量词；
- 排除一个指定邻域中的 No-three-in-line 修复，却把它误读成全局不存在性或已经得到 142 点构造；
- 在有限体积、截断或平滑 cutoff 下证明结论，却省略无限体积或去 cutoff 的桥。

**修复协议：** 每个证据必须包含 `statement_correspondence`。系统逐字比较其对象、量词、范围和假设与命题节点是否一致。局部定理可以晋升为局部定理，但不能自动提升目标节点。

### 2.2 `FINITE_TO_GLOBAL`：有限验证替代普遍证明

有限搜索可能产生：

- 反例；
- 猜想；
- 精确有限范围定理；
- 全局证明中的一个已证基例。

它不能独自承担“对所有 n”“对任意树”“对所有尺度”或“连续极限”的量词。No-three-in-line、优美树以及多种组合构造路线都暴露过这一风险。

**修复协议：** 将缺失量词独立成命题节点，例如“任意近外围有根树都存在兼容分解”。有限证书只连接到有限范围节点；全局节点需要归纳、紧性、有限基定理、结构分类或其他明确桥梁。

### 2.3 `DEPENDENCY_GAP`：最后一座桥被文字掩盖

常见句式是“由标准论证”“因此可以完成”“剩下只是技术细节”。实际缺口可能是整个问题的核心：

- 商环中的非直接有限元素已经得到，但群环角中的方程 `yx=f, xy≠f` 尚未解出；
- 构造了形式 cocycle，但模型空间的完备性、解析性或李代数识别没有闭合；
- 有紫外控制直觉，但反射正性、局部性、无限体积极限和谱隙并未由同一体系推出。

**修复协议：** 每一个“因此”生成一条依赖边。目标节点只能在所有父节点为 `PROVED` 时晋升。

### 2.4 `DEFINITION_DRIFT`：证明过程中定义发生变化

Banach–Lie initial subgroup 方向说明，弱 initial、strictly initial、浸入、嵌入和初始流形的定义不能混用。类似风险还包括：

- 连续逆代数在非完备与完备情形的不同定义；
- Hopf 型 Rota–Baxter 恒等式对余交换性的依赖；
- “解”“弱解”“分布解”“算子代数重构”的层级差异；
- “形式验证”“数值验证”“独立审计”的证据等级差异。

**修复协议：** 定义在首次出现时获得稳定 ID、来源、版本和适用边界。改变定义必须创建新版本命题，不能静默替换。

### 2.5 `TYPE_OR_DOMAIN_ERROR`：对象看似可组合，实际类型不匹配

高级数学推导最常见的隐蔽错误不是代数算错，而是：

- 算子没有共同定义域；
- 极限落在对偶空间而不是原空间；
- 乘积、卷积、余乘或积分所需完备性缺失；
- 映射在某拓扑下连续，但证明使用了更强拓扑；
- 局部坐标中的构造不能在图册交叠上粘合。

**修复协议：** 对象账本保存符号、类型、来源、用途、状态和边界。工具检查器首先验证类型合同，再验证公式。

### 2.6 `HIDDEN_ASSUMPTION`：对称性、线性或正则性被默认

Scale Transport Calculus 的审计暴露过：

- 一个 `iff` 实际只证明单向；
- 线性假设只在证明中使用、未进入定理陈述；
- 高阶余项需要额外一致控制；
- mixed high/low forest normal form 被证明不适合作为主线。

优美树路线也出现过把对称星层误当成一般组件层的风险。

**修复协议：** falsifier 逐项列出证明中第一次使用的性质，并反向检查定理输入是否声明。未声明性质自动成为阻塞义务。

### 2.7 `NON_INDEPENDENT_CHECKER`：生成器与检查器共享同一错误

一个程序输出证书，另一个程序调用同一核心函数验证，并不是独立审计。真实独立性至少需要一种差异：

- 不同实现；
- 不同算法；
- 不同形式系统；
- 从原始实例独立重建；
- 对证书做故意篡改并确认检查器拒绝。

**修复协议：** 每份证据有 `independence_group`。关键命题默认需要两个不同组；同组的十份输出仍只算一个证据源。

### 2.8 `LITERATURE_MISMATCH`：开放状态或引用条件未经核验

反例项目特别依赖精确文献状态：问题究竟仍开放、作者使用哪个定义、旧结果是否已经包含该例子。只凭摘要、二手叙述或记忆都不足以把“新反例”写进标题。

**修复协议：** 文献命题是证据对象，保存作者、版本、节号、引用片段和访问日期。未经核源的结果只能标为 `PROPOSED` 或 `PENDING_SOURCE_AUDIT`。

### 2.9 `ROUTE_DUPLICATION`：重复尝试被误计为并行探索

多 Agent 系统很容易生成十个措辞不同、证明机制相同的回复。它增加 token，却不增加搜索覆盖。

**修复协议：** 每条路线必须给出机制签名、独有不变量和能区分路线成败的测试。完全相同签名直接拒绝；高度重叠路线在仪表盘上合并。

### 2.10 `PROGRESS_SEMANTICS`：进度百分比被误读为成功概率

优美树 Harness 中的 82%、84%、87% 表示加权依赖节点完成，不是猜想为真的概率、已覆盖树的比例或剩余时间。No-three-in-line 的 82% 也不代表已有 142 点证书。

**修复协议：** v0.2 同时显示：

- `target_logical_closure`；
- `critical_path_closure`；
- 开放承重义务；
- release state；
- 指标语义声明。

只要目标节点没有闭合，`full logical closure` 仍为 0/1 中的 0。

### 2.11 `ABSTRACTION_WITHOUT_LOAD`：把高级结构硬接到问题上

无穷范畴、topos、量子群、Hopf 代数、Feynman 图等结构只有在承担明确证明义务时才进入主线。一个漂亮类比不自动产生定理。

**修复协议：** 新对象必须回答：

1. 它替代了哪个旧对象？
2. 它关闭哪个开放节点？
3. 它产生何种可证伪的新预测？
4. 删除它后证明在哪一步失败？

答不出来时，它只能进入 exploratory note，不能进入核心依赖图。

## 3. 成功模式

### 3.1 从普遍命题转向精确障碍

多个有效推进都来自把“大问题”压缩为一个精确、可攻击的对象：

- 把群环直接有限性压缩到角代数方程；
- 把优美树拼接压缩到 Toeplitz 位移 profile、重心条件和孔压缩；
- 把 No-three-in-line 局部修复压缩为冲突超图横截数；
- 把 initial subgroup 问题压缩到 sigma-compact closure obstruction；
- 把 CIA 完备化问题压缩到稠密 nil 子代数与完备化中非准逆元素。

这类压缩的价值在于：即使最终目标未闭合，也得到一个可独立发表或复用的严格中间定理。

### 3.2 反例优先的定义审计

当一个普遍命题涉及非闭、非完备、无限维或非正则对象时，先搜索最小病态例通常优于直接证明。有效模板包括：

- 对角紧算子和稠密真值域；
- 稠密幂零子代数的完备化；
- 非平凡解析 2-cocycle；
- 在有限前缀上消失、随后非零的多项式扰动。

### 3.3 证书与独立检查器双轨

组合研究中最可靠的交付不是“程序说 UNSAT”，而是：

1. 固定输入和哈希；
2. 生成证书；
3. 独立检查器从原始对象重建；
4. 检查退出码；
5. 篡改标签、边集、参数或哈希并确认拒绝；
6. 提供一条冷启动重放命令。

### 3.4 最强严格结论与目标结论分开

每轮结束必须同时输出：

- 本轮新闭合节点；
- 仍开放的承重义务；
- 最强无条件定理；
- 当前目标是否闭合；
- 禁止宣传的越界版本。

这使局部成果可以被正确评价，而不必通过夸大全局目标来体现价值。

### 3.5 失败传播而不是局部改字

若一个父命题被反例推翻，其后继命题必须自动变为 `BLOCKED` 或 `RETRACTED`。不能只修改出现反例的段落，同时保留依赖它的摘要、主定理和进度数字。

## 4. v0.2 的研究角色

### Strategist

选择下一承重节点；建立机制不同的路线；规定最低成本 kill test。

### Prover

一次只提交一个原子引理、精确归约、证书或形式证明候选。不得自行把候选标为已证。

### Falsifier

攻击量词、范围、边界、隐藏假设、定义版本和检查器语义。优先输出最小反例。

### Verifier

定义证据合同、重放命令、环境哈希、statement correspondence 和独立实现。

### Synthesizer

输出最强严格结论、开放义务、失败教训和下一轮合同。它没有越过验证门的权限。

## 5. 状态机

### 命题状态

```text
PROPOSED → OPEN → CANDIDATE → PROVED
                    ↓          ↓
                 BLOCKED    RETRACTED
                    ↓
                 REFUTED
```

`PROVED` 需要：

- 所有依赖为 `PROVED`；
- 至少一份 proof-capable evidence；
- 关键命题至少两个独立证据组；
- 精确或形式证据可冷重放；
- statement correspondence 完整；
- 没有未处理的范围越界。

语言模型输出只允许进入 `PROPOSED`、`OPEN`、`CANDIDATE` 或 `BLOCKED`。

### 路线状态

```text
PROPOSED → ACTIVE → CLOSED
                 ↘ BLOCKED
                 ↘ FALSIFIED
                 ↘ ABANDONED
```

### Release state

- `OPEN_RESEARCH`
- `CANDIDATE_UNVERIFIED`
- `BLOCKED_EXACT`
- `REFUTED_EXACT`
- `PROVED_WITH_AUDIT_DEBT`
- `PROVED_AND_AUDITED`

只有最后一个状态允许对合同中的目标作完成声明。

## 6. 下一版本的研究目标

v0.2 已建立协议和可运行内核。后续增强应优先于扩大提示词：

1. LeanDojo/LeanStar 适配器；
2. SAT/SMT/MILP/计算代数统一证据接口；
3. 文献命题与版本锁定；
4. 跨项目失败记忆数据库；
5. 机制签名的语义去重；
6. PutnamBench、miniF2F 和研究型开放问题切片上的同预算配对评测；
7. 人类数学家对 statement correspondence 和研究价值的双盲评分。

系统是否“更强”只能由这些固定协议下的结果决定，不能由架构图、单个演示或主观印象决定。
