MathArc 控制台开发蓝图

把「问题情报平面控制台」原型逐视图映射到 matharc/v02 后端的实施文档：哪些界面接线即活、哪些要新建、哪些被明确推迟，以及每一步的验收标准。原型本身是唯一的界面规范；本文不复述界面长什么样，只回答「怎么把它变成真的」。

§1定位与围栏

这份文档服务一个具体动作：让开发者拿着原型和仓库，直接开工。三条纪律贯穿全文，也贯穿实现：

  • 后端是唯一事实源。界面上任何计数、枚举、阈值，都必须能指回 matharc/v02 的具体文件；本文每个数字都带出处。原型开发期间共修掉四类与仓库不符的虚构（检索路线条数、扇出治理、停止条件计数、工具白名单成员），此类错误在实现期按缺陷处理。
  • 能力主张五态标注。每个视图属于且只属于一种建设状态：已落地（已有自动化证据）、待接线（后端已有，换真数据即可）、部分待建（后端有骨架，缺一截）、需新建（后端没有）、已推迟（设计文档明确推迟）。
  • 演示数据与真数据永不混排。接线一个视图的验收动作之一，就是删掉它的演示标注；未接线的视图保留标注。任何一屏出现无标注的编造数字，即为验收失败。
不在本文范围 数学内核本身（晋升门、精确工具、证伪通道的正确性）不归控制台改。控制台是这些机制的观察面与少数受控写口，永远不实现第二套判定逻辑；前端凡有复算（如证明链哈希），只为演示可核验性，判定仍以后端为准。

§2产品结构总览

控制台按研究的三个问题分三个平面，外加账户与管理端。三平面共 21 个视图，账户 4 个，管理端 6 个，落地页与登录 2 个全屏页。

§3原型技术架构

原型是单文件、零构建的静态页（约四千行）：一段 <style>、一段 <script>，无框架、无打包器，外部依赖仅 Google Fonts。这不是临时省事——在 M1 之前它就是交付形态，改一行刷新即见。

3.1运行模型

状态
单一 const S 对象：当前平面/视图、选中的进程与命题、各折叠态、篡改演示态等。
视图
V 注册表：每个视图一个纯函数，返回 {task, rail, main, side} 或 {page}（全屏页）。
渲染
render() 整页重渲染；输入框在渲染后按 id 找回焦点与光标位置。
事件
全局委托：data-act 分发点击；带 tabindex 的自绘控件响应回车/空格；data-cn 支持跳转视图时预选命题节点。
持久化
仅 localStorage 三个键：ma-theme（主题三态）、ma-view、ma-fold2（目录折叠），全部包 try/catch。
导航
每个平面一棵目录树（叶子 {v}／分组 {g,ctx,dim,kids}），路径式折叠键；面包屑只在祖先被收起时出现。
数据层
顶部一组 const 表（问题、命题图、路线、事件、评审队列……）。接线 = 用同构 JSON 替换这些常量，视图函数不动。

3.2组件清单

全部组件为模板函数 + 类名，无运行时抽象：card / pill / ev1–ev5 / banner / stat / kv / meter / gates / seg / chip，以及三件本项目特有的：链式手风琴（.cev，证明链、轮次、工具台账、观察队列、实验、推理共用；.chain.plain 变体去掉哈希咬合线）、难度画像标尺（.dprof，四条独立序数标尺，刻意不做雷达图）、翻译映射表（ETYPE / TSTATUS / ACTORROLE / STW / CST / TST …，后端枚举进 UI 的唯一通道）。

3.4三个高频改动怎么做

新增一个视图。四步：在 VMETA 注册名称与角标 → 挂进某平面的目录树（叶子 {v:"名"}，或带 ctx/dim 的分组）→ 写 V.名 = () => ({task, rail, main, side})（进程/问题作用域的视图先走 noDetail / noResult / noProblem 空态守卫）→ 交互用 data-act 挂进点击委托。约束即附C红线：枚举过翻译表、并排两栏过均衡阈值、主从用手风琴。

接线数据层。演示常量全部集中在上表数据区段，视图函数只读它们。M0 做法：启动时 fetch("console.json")，成功则以同构 JSON 覆盖这些常量、删除对应视图的演示标注，失败回落演示数据并在顶栏亮明数据源。逐视图接线，不整页切换。

本地预览与回归。预览零依赖：浏览器直接打开文件即可（字体走 Google Fonts，离线时回落系统字族）。回归六件套用 playwright-core 驱动本机 Chromium：全视图扫描、多宽度两栏均衡、篡改五模式、手风琴开合、开工流程、中英夹杂扫描——断言与阈值见 §9，任何一件红即不合并。

3.5与后端对齐的前端复算

证明链视图在浏览器内真实复算哈希：canon() 与后端 canonical_json 同口径（键排序、无空格、非 ASCII 不转义），事件字段与顺序照搬 ResearchEvent.unsigned_dict()，逐条校验照搬 EventLedger.validate() 的四项检查（含关键细节：previous 按事件声明的哈希前进）。五种篡改演示（改载荷/删除/对调/插入/整链重写）的错误签名各不相同，最后一种由链外发布的链头拦下。接线后此复算保留——它是「可核验」的现场证明，不是判定来源。

以下是控制台会触碰的全部后端事实，逐条给出处。实现时以代码为准；本节若与代码冲突，改本节。

4.2门与不变量（trace.py / falsification.py / review.py）

  • promote_claim 失败关闭：依赖未证全部报错（unproved dependencies）；关键命题要求两组来源独立的证明级证据（按 independence_group 计组）。
  • 被接受的证据必须可冷重放，否则报错；status=PASS 的工具调用不可重放会产生导出告警；关键命题携带不可重放证据直接报错。
  • promotion_route_blockers：命题的每条 ACTIVE 结构化路线（带 KillTestSpec）都必须有当前的 PASS_BOUNDED 记录，缺一即阻断——并行路线看集合的交。随机测试没找到反例永远记 INCONCLUSIVE，不记通过。
  • 评审：APPROVE 要求全部义务判定为 OK；评审记录版本绑定（命题修订即失配转 SUPERSEDED）；对象级回避规则 can_review 独立于角色权限。

4.3事件账本（event_log.py）

只可追加、哈希链式：validate() 四项检查（序号连续、前哈希咬合、事件哈希相符、事件编号唯一），previous 按声明值前进；to_dict() 携带 schema_version:"1.0" 与链头；public_summary() 导出时把载荷换成其摘要。文档串自我定位：不是区块链，只为检出删除、重排、插入、篡改。事件类型共 18 个，全部由工作区 _seal_transition 封存，载荷形如 {details, state_digest_after}。

4.4工具与证伪（exact_tools.py / smt_tools.py / lrat_tools.py / falsification.py）

精确工具白名单由注册表决定，default_exact_tool_registry() 当前恰五个模板：polynomial_identity / induction_certificate / smt_universal_no_counterexample / smt_existential_witness / cnf_lrat_unsat。信任语义非对称：unknown（含超时）记 ToolStatus.ERROR 永不产证据；sat 模型须过模块内独立纯 Python 求值器，二检不一致记错误；unsat 记求解器信任的精确计算并附局限声明。证伪测试是另一套注册表：KillTestKind 四类（enumeration / property_random / sat_search / instance_eval），只走负向通道——有限枚举不在精确工具白名单里。

4.5攻克运行时（campaign.py / orchestrator.py / prompting.py / budget.py）

  • 停止条件四分支：budget_exhausted / no_gain_rounds_exhausted / max_rounds_reached / release_state_terminal；默认 max_rounds=20、max_rounds_without_gain=5（每次攻克可另配）。
  • 单次提案扩张上限：5 命题 + 5 路线（orchestrator.py 常量）；无任何 spawn/子会话派生通道。
  • 五个工作者角色（prompting.py）：strategist / prover / falsifier / verifier / synthesizer，全部只能提案。
  • BudgetLedger：按工具调用与模型用量逐笔记账，exhausted() 判停。

4.6权限与评审面（authorization.py / review*.py）

15 项能力 × 8 个角色；整张矩阵里唯有「晋升门」持有 PROMOTE_CLAIM。评审对象：义务判定四值 OK / GAP / ERROR / CANNOT_JUDGE、整体决定三值 APPROVE / REQUEST_CHANGES / REJECT、生命周期三值 ACTIVE / SUPERSEDED / REVOKED、保证等级三档 MACHINE_SUFFICIENT / HUMAN_SINGLE / HUMAN_DOUBLE（同组不计独立）。此策略只管应用内权限，不认证人类身份、不替代系统隔离。

§7接口设计草案

原则照抄现有两个服务的纪律：读多写少，写口只有一个；观察站永远 GET-only，未识别路径一律 405/404 显式 JSON；令牌只用于唯一写口，不落存储。

7.1两种接线形态

  • 静态导出（M0，已落地）：cli.py export 将经审计工作区写为版本化 console.json，且拒绝写入工作区本身。控制台优先 fetch("console.json")，失败时清空陈旧快照、回落演示数据并顶栏披露来源。
  • 观察站直连（M1，已落地）：复用只读 GET /api/* 与 /events SSE；GET /api/campaign 仅返回绑定到当前工作区状态的报告。控制台作为观察站 dashboard 交付，事件触发合并为单次刷新。

附C设计红线

原型期逐条踩实的规则，实现期同权重于功能验收：

  • 禁发明数字。计数一律派生；协议参数（如检索路线条数）标注来源版本；「难度 87/100」式伪精度全站禁绝。
  • 禁雷达图于不同尺序数维度（各维五级名称互不相同）；四条独立标尺代替，面积是凭空造出来的量。
  • 禁总分。四个难度维度各自否决、各自补救，任何合成单值都落在禁令里。
  • 主从列表一律就地展开手风琴，不做左右分栏、不做弹窗——链的邻接关系必须同屏可比。
  • 并排两栏内容量必须相当（§9 阈值），做不到就重分内容或不并排；用对齐方式掩盖失衡视为缺陷。
  • 标识符必须以代码样式引用（.mono/.hash），后端枚举必须过翻译表；裸英文进中文文案按缺陷处理。
  • 空态诚实。无记录进程不借数据；被拒的晋升不产生事件——缺席本身是证据，界面不得补画。
  • 能力主张必须挂四态芯片；把计划说成现状（如扇出治理）是本项目定义的最高级缺陷。
