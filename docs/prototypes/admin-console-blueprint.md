# MathArc 管理员端蓝图

状态：设计稿与首期实现已落地；生产启用需完成迁移和反向代理配置。  
范围：邀请码申请审核、签发、撤销、会话和审计。  
原则：管理员控制面与公网研究预览面分离；所有写操作可追溯；邀请码明文只出现一次。

## 1. 目标用户与权限

| 角色 | 可见范围 | 允许操作 |
| --- | --- | --- |
| `access_admin` | 申请、邀请码、会话、审计 | 查看申请；签发和撤销邀请码；查看会话元数据；导出脱敏审计 |
| `access_reviewer` | 申请、邀请码只读、审计只读 | 查看申请详情、邀请码状态和审计记录 |
| `security_admin` | 安全设置、全部审计 | 管理管理员、强制失效会话、配置保留期 |

第一期只实现 `access_admin`，采用服务器侧会话 + MFA（TOTP 或硬件密钥）+ IP/设备审计。SSH/sudo 继续保留为 break-glass 运维入口，不作为网页登录的后门。

## 2. 页面结构

### `/admin/login` 登录

- 登录由 OIDC、Cloudflare Access 或同等反向代理完成，应用不接收密码或 MFA 秘密。
- 反代在转发时注入完整的 `X-Admin-*` 身份头，并清除客户端同名头。
- 应用只在 `MATHARC_ADMIN_TRUST_PROXY=true` 时接受管理员路由；公网研究预览 Cookie 不具备管理员权限。

### `/admin` 总览

顶部显示：待处理申请数、有效邀请码数、近 24 小时兑换数、活跃会话数、最近一次状态校验时间。

主体采用三栏控制台：

1. 左侧导航：总览、申请、邀请码、会话、审计、安全设置。
2. 中间工作区：当前队列或列表，支持状态筛选、邮箱搜索、时间范围和分页。
3. 右侧详情：选中记录的完整元数据、风险提示和允许的下一步。

高风险动作使用显式确认抽屉，确认内容必须包含对象 ID、目标邮箱、作用域、过期时间和操作者身份。

### `/admin/applications` 申请队列

列表字段：状态、邮箱、机构、研究角色、研究方向摘要、提交时间、关联邀请码数。  
详情显示申请原文和处理历史。第一期状态仍沿用当前 `PENDING`，审核通过动作调用签发流程，不在申请记录上引入未经定义的状态值。

### `/admin/invitations` 邀请码

列表字段：邀请码 ID、邮箱、主题作用域、签发时间、过期时间、状态（有效/已兑换/已撤销/已过期）。不显示 `code_hash_sha256`，也不提供“查看明文”。

“签发邀请码”表单：邮箱、主题作用域（可多选）、有效期。提交前展示摘要并要求 MFA 二次确认。成功后进入一次性结果页：

```text
邀请码仅显示一次
<code>
[复制] [下载一次性文本]
关闭后无法恢复，请通过安全渠道发送给指定邮箱。
```

结果页禁止 URL 持久化明文，禁止浏览器 localStorage，禁止分析埋点记录输入内容；关闭、刷新或离开页面后立即清除。

撤销只允许对未兑换且未撤销的邀请码执行。撤销后要求填写原因，原因写入审计事件。

### `/admin/sessions` 会话

只显示会话 ID、邮箱、主题作用域、创建时间、过期时间、最后活动时间和状态。提供“强制退出”给 `security_admin`；普通管理员只能查看。

### `/admin/audit` 审计

不可修改、追加式事件流。字段：事件 ID、时间、操作者、动作、对象类型、对象 ID、结果、原因、请求来源、事件摘要哈希。支持按操作者、动作、结果和时间范围筛选；导出内容自动脱敏。

## 3. 管理 API 草案

管理 API 使用独立前缀 `/api/admin`，与现有公网 `/api/access/*` 分开部署或至少分开认证中间件。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/admin/auth/login` | 保留兼容占位；实际登录由反向代理完成，应用返回 `401 proxy_auth_required` |
| `POST` | `/api/admin/auth/logout` | 失效管理员会话 |
| `GET` | `/api/admin/me` | 当前管理员与权限 |
| `GET` | `/api/admin/applications` | 分页申请列表 |
| `GET` | `/api/admin/applications/{id}` | 申请详情 |
| `GET` | `/api/admin/invitations` | 脱敏邀请码列表 |
| `POST` | `/api/admin/invitations` | 调用 `InvitationAccessStore.issue_invitation(...)` |
| `POST` | `/api/admin/invitations/{id}/revoke` | 调用 `revoke_invitation(...)` |
| `GET` | `/api/admin/access-sessions` | 会话元数据 |
| `GET` | `/api/admin/audit` | 审计查询 |

签发响应只返回一次性 `code` 和 `invitation.to_dict()`；服务端日志、审计日志和异常消息均不得写入明文。所有写接口要求幂等键、CSRF 防护、重新验证 MFA，并记录成功与失败事件。

## 4. 存储与迁移

当前 `/var/lib/matharc-research/access/access-state.json` 继续由 `InvitationAccessStore` 维护。第一期可以增加同目录的管理员状态文件，但更稳妥的生产方案是迁移到 SQLite/PostgreSQL，并保留状态摘要校验和原子写入语义。

建议新增：

- `admin_users`：管理员身份、角色、MFA 公钥/密钥引用、禁用时间。
- `admin_sessions`：会话哈希、创建/过期/撤销时间、设备与来源摘要。
- `audit_events`：追加式审计事件及链式摘要。

迁移必须先做只读导入和摘要比对，再切换写入；旧 CLI 入口在网页稳定前保留。

## 5. 分阶段交付

**MVP-A：只读控制面**

- 管理员登录、申请列表、邀请码脱敏列表、审计读取。
- 不改变公网路由，不允许网页签发。

**MVP-B：签发与撤销**

- 新增管理 API，接入现有 store 方法。
- 一次性明文结果页、MFA 二次确认、幂等键和审计事件。

**MVP-C：安全运营**

- 管理员与角色管理、会话强制失效、异常告警、备份恢复演练。

## 6. 验收门槛

- 未登录、普通预览会话和 `access_reviewer` 均无法调用写接口。
- 公网路径不存在邀请码签发能力；现有申请、兑换、会话接口回归测试通过。
- 任意邀请码明文只在签发响应和一次性页面出现一次，刷新后不可恢复。
- 撤销已兑换邀请码返回冲突；重复撤销返回冲突；状态摘要校验失败时所有管理写操作 fail closed。
- 每次签发、撤销、失败尝试均可按管理员、对象 ID 和时间查询到审计记录。
- 桌面 1440px、平板 1024px、移动 390px 下，列表、详情、确认抽屉无重叠且键盘可操作。

## 7. 当前明确不做

- 不把管理员入口挂到现有公网预览会话上。
- 不在浏览器保存邀请码明文或哈希。
- 不通过“隐藏 URL”“前端角色字段”代替服务端授权。
- 不把 SSH 命令历史当作网页审计记录。
